## چهار ایراد اصلاح‌شده

### BIZ-01 — خرید پس از حذف پیش‌نویس

درخواست هنگام ساخت پیش‌نویس به `IN_PROGRESS` می‌رود؛ هم‌زمان فقط یک برنامه می‌تواند خرید را رزرو کند. حذف پیش‌نویس، درخواست را به `REQUESTED` برمی‌گرداند. تنها انتشار برنامه، `FULFILLED` و زمان تحویل را ثبت می‌کند. پیش‌نویس برای ورزشکار قابل مشاهده نیست. انتشار پیش‌نویس متعلق به درخواست لغوشده نیز رد می‌شود.

تست، زنجیره خرید → پیش‌نویس → حذف → ساخت مجدد → انتشار → مشاهده ورزشکار را بررسی می‌کند. حذف نسخه‌ای که قبلاً تحویل شده، خرید را مجدداً باز نمی‌کند.

### BIZ-02 — تفاوت مبلغ دیده‌شده و مبلغ خرید

API عمومی خرید، توکن امضاشده پیشنهاد با اعتبار ۱۵ دقیقه می‌خواهد. تغییر قیمت یا شرایط مؤثر و انقضا، خرید را با `training_quote_changed` متوقف می‌کند. فرم پیشنهاد جدید را نشان می‌دهد و تأیید مجدد لازم دارد. پیشنهاد داخل دیالوگ از refetch پس‌زمینه مستقل است. retry موفق قبلی با همان کلید، پرداخت یا سفارش جدید ایجاد نمی‌کند.

تست‌ها تغییر قیمت بین نمایش و تأیید، توکن جعلی/منقضی و idempotency را پوشش می‌دهند.

### BIZ-03 — خطای پلن ورزشکار

حالت خطا از نبود پلن جدا شد. تزریق ۵۰۳، پیام خطا و دکمه تلاش مجدد نشان می‌دهد؛ پیام نادرست «پلن فعال تعریف نشده» نمایش داده نمی‌شود. پس از بازیابی سرویس، خرید دوباره در دسترس است.

### BIZ-04 — خطای صف مربی

خطای دریافت درخواست‌ها مستقل از خالی بودن صف نمایش داده می‌شود. تزریق ۵۰۳ به‌صورت «درخواستی ثبت نشده» پنهان نمی‌شود و امکان تلاش مجدد دارد.

## صحت و دسترسی قابلیت‌های جدید

- API صورت‌حساب مربی، شناسه مربی دلخواه از کاربر دریافت نمی‌کند و فقط سهم همان حساب را برمی‌گرداند؛ گزارش کل باشگاه برای مربی باز نشده است.
- سند خرید به باشگاه و ورزشکار صاحب فروش محدود است و سهم‌های سایر اشخاص را افشا نمی‌کند.
- ثبت عملکرد فقط توسط خود ورزشکار مجاز است. مربی/مدیر مجاز، سابقه را می‌خواند و به جای ورزشکار ثبت نمی‌کند.
- تاریخ آینده، مقادیر خارج از محدوده و شناسه ست متعلق به روز دیگر رد می‌شوند. retry با همان داده تکرار ایجاد نمی‌کند و استفاده از همان کلید برای داده متفاوت رد می‌شود.
- اهداف و نام‌های هنگام ثبت، snapshot مستقل دارند؛ تغییر اهداف و حذف برنامه، نتیجه ثبت‌شده را بازنویسی یا حذف نمی‌کند.
- شناسه واقعی روز و ست در پاسخ جزئیات برنامه اضافه شد؛ نسخه‌های کپی/قالب همچنان شناسه‌های مستقل خودشان را می‌گیرند.
- در پرونده ورزشکار، ترتیب تب‌های قبلی و شروع روی «برنامه‌ها» حفظ شد و تب چهارم «تمرین و پیشرفت» اضافه شد.

## راه استفاده

- **مدیر/مربی:** داشبورد باشگاه → «کارهای امروز».
- **مربی:** «پلن و درخواست‌ها» → «صورت‌حساب من» و صف درخواست‌ها.
- **ورزشکار:** «برنامه من» → وضعیت درخواست → «فاکتور و رسید» یا «مشاهده برنامه تحویل‌شده».
- **ثبت تمرین:** مشاهده برنامه → انتخاب روز → «ثبت عملکرد این جلسه».
- **بررسی مربی:** پرونده ورزشکار → تب «تمرین و پیشرفت».

نسخه اول سابقه، آخرین ۱۰۰ جلسه را نمایش می‌دهد و ویرایش رکورد ثبت‌شده از UI ندارد. مقایسه عملکرد مبتنی بر گزارش ورزشکار است و تأیید انجام واقعی تمرین یا ارزیابی پزشکی محسوب نمی‌شود.
