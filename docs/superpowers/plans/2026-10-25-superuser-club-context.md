# Superuser Global Context Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop binding superusers to a club on login, give them a global dashboard, and let them enter a club's workspace through real `/gyms/:gymId` routes.

**Architecture:** Keep the existing FastAPI/SQLModel backend untouched. On the frontend, gate the automatic club selection on `me.is_superuser`, render a global dashboard when a superuser has no active club, and replace the `/gyms/:gymId` detail route with a club-workspace layout that syncs the active club from the URL, moving today's detail page to `/gyms/:gymId/settings`. Club users keep today's behavior.

**Tech Stack:** React 19, TypeScript, TanStack Router (file-based), TanStack Query, Vite, Playwright, Biome.

**Spec:** `docs/superpowers/specs/2026-10-25-superuser-club-context-design.md`

## Global Constraints

- No backend, API, schema, migration or permission changes.
- Owners, coaches and athletes must see no behavior change.
- Superuser sees no club name or mode chip until they enter a club; entering sets the club for the whole workspace; "all clubs" clears it.
- Fresh login always returns a superuser to the global view; reload inside a club keeps that club.
- Persian is the primary UI language; every new string needs a Persian and an English entry.
- Biome clean (`bun run lint:check`), TypeScript clean, no new dependencies.
- Tests use only disposable databases; never reset or migrate the development database.

## Review Focus

- A superuser with **zero clubs** must see the existing empty state and the create-club action, not a blank global dashboard.
- A superuser who is **also a club member or owner** must still see their real roles inside the club (role chip/switcher), and must not lose access by leaving.
- **Reload** at `/gyms/:id` or `/gyms/:id/settings` must restore the club context; a direct deep link must not land in the wrong club.
- A **non-superuser** opening `/gyms` must not lose their active club (only superusers clear context there).
- **Leaving** a club from any inner page (e.g. `/athletes`) via "all clubs" must clear context and land on `/` in the global view, with stale club-scoped queries gone.

const setActiveGym = useCallback(
  (gymId: string | null) => {
    if (gymId === null) {

      localStorage.removeItem("gym.activeRole")
      setActiveGymIdState(null)
      setActiveRoleState(null)

      localStorage.setItem("gym.activeGymId", gymId)

    queryClient.removeQueries({

`_app.gyms.$gymId.tsx` becomes a layout that syncs the URL to the active club:

```tsx
import { createFileRoute, Outlet } from "@tanstack/react-router"
import { useEffect } from "react"
import { useAuth } from "@/auth"

function ClubLayout() {
  const { gymId } = Route.useParams()
  const { setActiveGym } = useAuth()
  useEffect(() => {
    setActiveGym(gymId)
  }, [gymId, setActiveGym])
  return <Outlet />
}

export const Route = createFileRoute("/_app/gyms/$gymId")({ component: ClubLayout })
```
